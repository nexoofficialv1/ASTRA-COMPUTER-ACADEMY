# Architecture v1.0

Offline-first, practical-first learning. Bundled curriculum declares theory, quizzes, performance targets and simulator tasks; deterministic local engines assess learner work without internet access.

## Core layers
- `assets/content`: bundled curriculum and practical task definitions
- `models`: Course / Lesson / Quiz / Learner Profile
- `services/ContentRepository`: curriculum loader
- `data/AppDatabase`: SQLite persistence and migrations
- `services/ProgressRepository`: progress + append-only practical attempt history + activity streak
- `services/WordPracticalEvaluator`: text / formatting / table validation
- `services/ExcelFormulaEngine`: local spreadsheet formula evaluation including IF/COUNTIF/SUMIF/VLOOKUP
- `services/ExcelPracticalEvaluator`: value / formula / task validation
- `services/MasteryService`: deterministic mastery scoring
- `services/AchievementService`: badges
- `services/FinalExamService`: final practical composition/pass policy
- `services/CertificationRepository`: offline certificate record
- `services/BackupRestoreService`: local JSON portability
- `services/CertificateExportService`: text/HTML certificate representation
- `services/CertificatePdfService`: local printable PDF file generation from rendered certificate image
- `screens`: lesson, quiz and practical lab flows

## Practical routing
- `typing` -> Typing Lab
- `data_entry` -> Data Entry Lab
- `word_workflow` -> Word Save/Page/Print Lab
- `word_page_elements` -> Word Header/Footer/Page Number Lab
- remaining `word_*` -> Word document Lab
- `excel_workflow` -> Excel Sort/Filter/Chart/Print Lab
- remaining `excel_*` -> Excel formula/grid Lab
- `windows_file_manager` -> offline File Manager Lab
- `windows_desktop` -> Desktop/Start/Taskbar Lab
- `keyboard_shortcuts` -> virtual keyboard Shortcut Lab
- `internet_browser` -> offline Browser Lab
- `email_compose` -> offline Email Lab
- `powerpoint` -> PowerPoint Slide Lab
- `office_project` -> integrated Office Project Lab

The curriculum remains the source of task definitions, so new exercises can usually be added without changing evaluator structure.

## Excel engine scope in v0.8
Supported locally: arithmetic, SUM, AVERAGE, MIN, MAX, COUNT, IF, COUNTIF, SUMIF and exact-match VLOOKUP. This is an educational subset rather than a full Excel-compatible calculation engine.

## Safety boundary of simulators
Windows, Word workflow, PowerPoint and Internet practicals are sandboxed learning simulations. They do not modify real device files, print to a real printer, or require live website access.

## Data portability
The SQLite schema stores stable lesson IDs and append-only attempts. `BackupRestoreService` serializes learner-owned state into a versioned JSON envelope. This remains transport-agnostic so later Android/Web/Windows sync can reuse the same logical record model.

## Future multi-platform direction
Flutter UI and curriculum/task models remain suitable for Android, Web and Windows. Device-specific functions such as file picker, share sheet, real printing and cloud sync should remain behind services/adapters rather than inside curriculum or assessment engines.

## v0.8 practical engines
v0.8 adds four curriculum-driven practical surfaces:
- `WordPageElementsLabScreen` for Header/Footer/Page Number.
- `ExcelWorkflowLabScreen` for Sort/Filter/Chart/Print workflow state.
- `WindowsDesktopLabScreen` for Start/Taskbar/window lifecycle actions.
- `EmailLabScreen` for offline To/CC/Subject/Body/Attachment/Send training.

All four persist attempts through the existing generic `ProgressRepository.recordPracticeAttempt`, so no database schema migration is required.

## Certificate PDF strategy
`CertificateScreen` renders the existing Flutter certificate card through `RepaintBoundary`, converts it to PNG, and `CertificatePdfService` embeds that image into an A4 landscape PDF. This avoids requiring a bundled PDF font solely to preserve Bengali/Unicode visual rendering in the certificate preview.


## v0.9 presentation/navigation layer
The learning engines and SQLite schema are unchanged. v0.9 adds a presentation layer around the existing flows:
- `AppTheme`: ASTRA navy/royal-blue design tokens, cards, controls, navigation and dark-theme foundation.
- `BrandMark` + `SplashScreen`: reusable visual identity.
- `HomeScreen`: progress-first dashboard and bottom navigation entry points.
- `CourseLibraryScreen`: compact all-course navigation.
- `PracticalHubScreen`: practical-first navigation across courses.
- `CourseDetailScreen`: separated Lessons/Practicals tabs while preserving sequential unlock rules.

The approved mockup is retained in `docs/UI_REFERENCE_v0.9.png` as a visual acceptance reference; it is not shipped as a runtime asset.


## v1.0 Android build layer
Android native boilerplate is intentionally generated by `scripts/bootstrap_android.sh` using the Flutter SDK that performs the build. `scripts/apply_android_branding.py` then overlays only ASTRA-owned resources and manifest policy. This separates volatile Flutter/Gradle template details from stable application code/content. The GitHub Actions pipeline uses the same bootstrap path as local builds.

The main release manifest policy is offline-first: no ASTRA INTERNET, broad storage, camera, microphone, contacts or location permission is introduced. Cleartext traffic and Android system backup are disabled. Debug/profile manifests generated by Flutter may differ because Flutter tooling can require development-only networking.
